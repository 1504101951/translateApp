## 当前原则

1. 当前产品平台为macOS 26+，不包含Android、iOS或Windows客户端。
2. Selection Gesture包括鼠标拖拽、双击、三击、Command-A，以及Shift配合方向/Home/End/Page键产生的文本选区。
3. Translation Overlay不抢来源应用焦点；自动小按钮随选区/来源失效结束，展开卡片仅通过Escape或×关闭，全局翻译快捷键可显式替换。
4. 只翻译Text Selection Context；文件树和表格不是文本上下文，聊天列表可按实际文本上下文判断。
5. 平台实现职责与测试分层见[架构设计约束](architecture.md)，组件几何与颜色见[样式规格](style.md)。

## 问题陈述

浏览器扩展可以翻译网页中的选中文本，但无法覆盖原生 macOS 应用。用户需要一款轻量级的全局翻译工具：在鼠标选中文本后于读取完成时的鼠标位置旁显示可拖动浮层，等待用户明确点击后才把文本发送给第三方，并以一致方式接入 Google 翻译和语言模型。

产品还需要在不破坏段落的前提下处理长文本，把流式与非流式提供方统一为相同的数据流，在本地保存翻译历史，并明确展示凭据、隐私、费用和失败状态。

## 解决方案

构建 macOS 26+ 菜单栏应用。应用层为 Flutter/Dart；macOS 系统能力经 Swift 平台通道接入。

鼠标选区手势、Command-A 或 Shift 导航扩选（Selection Gesture）在辅助功能可读取选中文本、处于 Text Selection Context、且源应用未被排除时创建选区会话（Selection Session）。可拖动的翻译浮层（Translation Overlay）显示在读取完成时的鼠标位置旁，初始处于翻译触发状态（Translation Trigger State）；用户点击后，应用在本地检测语言、确定翻译方向（Translation Direction），并把标准化请求发送给默认翻译提供方（Default Translation Provider）。浮层随后进入翻译结果状态（Translation Result State），消费统一的翻译更新（Translation Update）。

Overlay 是非激活面板，不成为 Key Window，不改变前台应用。自动 Trigger State 随选区/来源失效结束；已展开的加载、完成、失败和超限 Result State 不因切 App、选区清空、外部点击、新被动选区或设置修改关闭。Escape 或 × 关闭结果，全局翻译快捷键可显式发起替换。

第一版支持 Unofficial Google Provider、Official Google Provider、多组 OpenAI-Compatible Provider 配置和多组 Anthropic Provider 配置。所有第三方协议均由 Dart 适配层转换为同一种内部请求、更新、完成和失败数据流。

长文本使用有序的分段翻译（Segmented Translation）。分段保留段落结构，并为模型提供方携带有界的滑动翻译上下文（Sliding Translation Context）。完整成功的翻译可以写入本地 SQLite，并在独立历史窗口中滚动浏览。

## 用户故事

1. 作为 macOS 用户，我希望在原生应用和浏览器中都能翻译选中的文本。
2. 作为读者，我希望鼠标拖拽、双击或三击选中文字后，在读取完成时的鼠标位置旁看到翻译浮层。
3. 作为用户，我希望 Command-A 全选或 Shift 导航扩选可读文本后同样出现浮层。
4. 作为用户，我希望浮层先等待点击，避免仅选中文字就产生外部请求和费用。
5. 作为用户，我希望触发按钮整体和结果框顶部 56pt 标题区均可拖动，并保持当前位置；正文选字、复制和 × 与拖动区域独立。
6. 作为用户，我希望自动按钮随新选区更新；展开后的译文框一直保留，只有 Escape 或 × 关闭，也可通过全局翻译快捷键主动替换为新译文。
7. 作为用户，我希望 Overlay 出现时源应用仍保持激活，选区高亮不消失。
8. 作为用户，我希望默认对辅助功能可读取文本的应用启用，并能永久排除指定应用。
9. 作为新用户，我希望默认使用零配置的 Unofficial Google Provider，并明确知道它可能失效。
10. 作为 Google Cloud 用户，我希望配置 Official Google Provider，并将其设为默认提供方。
11. 作为模型用户，我希望创建多组具名 OpenAI-compatible 与 Anthropic Model Profile，并独立编辑模型、端点和 Translation Prompt。
12. 作为用户，我希望 API 密钥只保存在 macOS Keychain 中。
13. 作为用户，我希望每个提供方都经过统一接口层，调用方不处理第三方响应结构。
14. 作为模型用户，我希望模型结果流式显示；Google 一次性结果也转换为至少一条相同类型的更新。
15. 作为用户，我希望提供方失败时明确显示错误，不自动把文本发送到另一家公司。
16. 作为用户，我希望在设备本地检测源语言，并让所有提供方使用相同的语言判断和翻译方向。
17. 作为用户，我希望主要语言默认取第一个 macOS 首选语言，次要语言为可选项，默认不设置。
18. 作为双语用户，我希望设置次要语言时，主要语言文本译为次要语言，其他或未知语言译为主要语言；未设置次要语言时统一以主要语言为目标，已是目标语言的文本直接展示而不请求服务。
19. 作为用户，我希望主要语言和可选次要语言可编辑并持久保存，次要语言清空后仍保持未设置。
20. 作为用户，我希望选区最多支持 50,000 个字符，超限时仅在本地提示且不发起第三方请求。
21. 作为长文读者，我希望内部切片对我不可见，结果始终按原文顺序显示为连续译文。
22. 作为长文读者，我希望每片目标约 4,000 字符，并允许延长至 6,000 字符以保持段落完整。
23. 作为长文读者，我希望超过 6,000 字符的单段先按句子边界拆分，单句仍超限时才硬切。
24. 作为模型用户，我希望下一片只携带前一片原文尾部 1,000 字符和译文尾部 1,000 字符，兼顾上下文一致性与请求大小。
25. 作为用户，我希望 Google 提供方忽略不支持的滑动上下文，但仍使用统一请求流程。
26. 作为用户，我希望分片串行翻译，输出顺序稳定并降低限流风险。
27. 作为用户，我希望某片失败后保留已完成结果，并能从失败片继续重试。
28. 作为用户，我希望取消、失败或未完成的翻译不进入历史。
29. 作为用户，我希望每次成功翻译都独立写入历史，不对相同原文去重。
30. 作为用户，我希望历史保存原文、译文、检测语言、目标语言、提供方、可选模型和完成时间，以及来源应用显示名，但不保存选区坐标。
31. 作为用户，我希望历史默认启用且可关闭未来写入，同时保留已有记录。
32. 作为用户，我希望从菜单栏打开独立历史窗口，最新记录优先，每次滚动加载 10 条。
33. 作为用户，我希望登录时启动默认关闭，只有明确开启后才生效。
34. 作为首次使用者，我希望得到清晰的辅助功能权限说明。
35. 作为在安全输入框、文件树或不受支持应用中操作的用户，我希望不可读取或不属于文本选区时不显示误导性浮层。

1. 截图编辑工具栏提供“截图”工具组，在第二行提供“录制”和“滚动长截图”二级入口；“截图”主工具承担区域裁剪，沿用已有顺序、显隐与快捷键。点击录制后在同一工具栏增加目标行，提供当前选区、窗口、全屏；点击窗口继续增加可滚动的应用图标行，不使用下拉或独立菜单。应用图标点击选中、悬停显示应用名，提供选中状态、键盘焦点与可访问名称；切换目标清除应用选择并隐藏不适用行。重复点击不重复增行。开始操作提交当前目标，取消保留编辑内容。全屏绑定截图来源显示器。长截图点击后立即沿用当前选区开始，区域边框持续可见且不可移动、缩放或编辑，不再要求第二次开始。媒体结果图片不具备屏幕采集身份，采集入口禁用。菜单栏保留普通区域截图和停止采集。一次只允许一个录屏或滚动采集会话；采集期间暂停被动选区翻译并隐藏本应用翻译浮层。
2. 录屏支持显示器、应用全部可见窗口与屏幕区域，使用30fps、无音轨的H.264 MP4。应用按身份去重，发起截图前正在操作的应用排第一，其余顺序稳定；截图窗口获得焦点不改变排序依据。应用录制以开始时所有显示器按桌面排列组成固定联合画布，保持窗口桌面位置，其他应用与空白区域填黑；窗口移动、新开和关闭均按所选应用更新。画布使用统一最高显示倍率保留各屏细节；显示器连接、排列或倍率变化、应用退出、没有可录目标、权限失效或编码器不支持画布时明确停止并保留已确认内容，不改录其他来源。单屏与区域保留原生分辨率。开始前检查屏幕录制授权；本应用的阴影、选区边框和悬浮操作按钮全部排除出捕获。录制期间显示实时画面与选区外阴影，鼠标和键盘交给来源应用；应用目标覆盖固定联合画布中的全部可见窗口，不以某个窗口标题作为选择层级。录制与长截图共用右下角的四个独立气泡：状态、暂停／开始、结束、放弃；录制状态显示“录制：时间”，长截图状态显示实际长图高度。整体背景透明，悬停描述显示在气泡上方。暂停保留已有内容，开始继续追加；暂停时长不进入视频内容与录制时长。结束后完成编码并进入结果处理；放弃须二级确认弹窗，取消确认继续保留当前状态，确认才清理会话临时内容。用户通过系统保存面板保存视频，保存取消保留预览；不将编码中、失败或临时文件显示为已保存。
3. 已完成录屏可预览、保存MP4或导出GIF；GIF输入只读当前录制，用户指定起止秒数、1–30fps帧率与输出宽度，默认10fps、原宽，保持纵横比且不放大。显示所选时长、输出尺寸与进度，可取消。起止须有限且满足0≤开始<结束≤视频时长；帧数量上限1800，超限在转换前说明。按真实采样时间顺序编码，最后一帧延时覆盖片段余量。保存面板取消不修改源视频；转换取消/失败清理临时GIF，完成后原子发布文件。
4. 长截图为手动向下滚动：框选后点击截图工具栏“截图”组的“滚动长截图”立即开始，固定选区边框和选区外阴影持续显示，来源应用直接接收滚轮，不注入滚动事件。顶部与底部固定内容由实际正文位移自动识别，空白或静止画面不能单独证明固定导航；须用可靠正文位移区分固定像素与偶然重合的正文空白，不因正常内容进入边缘空白而误报固定区域变化；启动后不展示可编辑边界线或选区调整控件。暂停不追加帧，开始后从保留的拼接内容继续；恢复时若不能安全匹配，则按拼接失败规则处理已有内容。
5. 长图为“第一帧顶部固定区＋连续去重正文＋最后一帧底部固定区”。中间帧的上下固定区不参与位移计算或重复追加；顶部导航与底部工具各保留一次。局部悬浮按钮按自动识别的固定区域处理；最终底部按钮及其原始遮挡保留，不生成或推测被遮文字。自动固定区域不能可靠识别时停止并说明，保留已确认部分。
6. 拼接仅接受可靠的同宽、同缩放、垂直位移及有效正文重叠；滚动太快、反向滚动、导航边界改变、布局变化或动态内容导致不可靠匹配时停止并说明，可预览已确认的部分，不能标记完整成功。暂时静止只等待继续操作；用户点击结束，无有效位移则说明未形成长图。原图像素总量上限33554432、最长边32768像素，超限停止并保留已确认部分；取消清理所有会话产物。
7. 录制与长截图采集、暂停期间均显示紧凑全局悬浮控制条和实时选区遮罩；准备、暂停切换及完成编码阶段显示实际状态并禁止重复提交。结束长截图后直接进入现有图片编辑器，提供PNG保存、复制和贴图；结束录制后显示视频结果与导出选项。控制UI和辅助线不进入导出图。准备按钮使用独立玻璃材料和明确命中尺寸；工具栏按实际行数定位，在全屏、贴边、横竖布局与不同倍率下完整位于来源显示器可用范围内，选区外放不下时进入选区内，不改变捕获像素。显示器和区域绑定实际显示器身份与像素倍率；跨显示器框选不静默拼接不同倍率，要求重新选择单个显示器中的区域。
8. 自动化验证包含固定顶部/底部及悬浮按钮区域的像素连续性、静止/反向/歧义/超限停止、GIF帧顺序与总延时、取消清理和视频可解码。权限、真实窗口录制、多屏及Chrome网页/静态列表的效果由用户验收。所有内容仅在本地处理。

退出应用时，若存在活动采集或未处理结果，提示返回采集或退出并丢弃；确认后等待后台任务取消与私有临时目录清理。已保存文件不受影响。暂停与放弃确认期间仍保留会话所有权，不能启动第二份采集。
