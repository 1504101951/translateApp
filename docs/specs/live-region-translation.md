## 已确认结论

1. **入口与捕获目标**
   1.1 实时翻译是截图中的工具，不提供专用快捷键。
   1.2 复用录制准备流程，选择区域、窗口或全屏后点击开始；准备阶段不启动持续 OCR 或翻译。
   1.3 “窗口”沿用录制的应用 Bundle ID 契约，捕获该应用的窗口集合；全屏沿用截图来源显示器。
   1.4 窗口、全屏、捕获及范围标记复用现有能力和样式。画面帧直接送设备 OCR，不生成录屏文件。

2. **结果窗口**
   2.1 原文在上、译文在下，两区独立滚动。
   2.2 准备阶段显示结果预览，允许拖动和缩放；点击开始后尺寸与位置锁定，暂停不解除锁定。
   2.3 需要调整时先结束或放弃本次会话，再独立启动实时翻译并设置；不继承前次窗口调整。
   2.4 不抢来源应用焦点；运行中不占用来源应用 Escape。
   2.5 顶部菜单栏图标显示中止按钮，点击执行结束语义；结束或放弃后恢复普通图标。

3. **活动控制与会话边界**
   3.1 暂停／恢复、结束、放弃使用录制和滚动长截图的同一活动控制条，沿用业务语义，不另造控制组件。
   3.2 暂停停止本次捕获、OCR 与网络工作并保留本次会话；恢复沿用同一捕获目标，重新识别当前画面。未变化且已成功的文字不重复发送。
   3.3 结束停止后台工作，保留本次最后已显示结果并标注“已结束”；不等待后续翻译完成。
   3.4 放弃取消工作、清理本次内容并关闭结果窗口；关闭结果窗口同样按放弃语义处理。
   3.5 每次启动独立会话，无活动会话内更换目标入口。不持久化或继承前次目标、原文、译文、分段进度、去重记录、失败任务、窗口调整及运行状态；不自动写入历史。
   3.6 本次运行只保留去重、调度与拒绝迟到事件所需的内存状态。应用全局服务设置不是会话记录；资源释放期间的在途槽位不得提前复用。

4. **请求与失败处理**
   4.1 不提供手动重试入口。只有最新有效文字可进入发送候选，旧失败任务不排队。
   4.2 同一文字已有活动请求或已经成功时，不重复发送。
   4.3 当前文字请求失败后，后续有效 OCR 若仍为同一文字且无活动请求，可在满足请求开始间隔后再次发送。再次失败仍按此规则处理；文字变化立即废弃旧失败候选。
   4.4 本地输入校验不通过时不发送网络请求；不自动切换 Provider。
   4.5 单纯修改服务、目标语言或模型不打断当前请求，也不重译未变化的文字；下一次文字变化时生效。每个内容修订保持一致的配置快照，失败重发沿用该快照；独立新会话使用开始时的当前设置。

5. **性能配置**
   5.1 采集间隔 200ms、文字合并等待 200ms、请求开始间隔 500ms 为已批准初始值。
   5.2 三个值集中为命名配置项，注明毫秒单位与作用，便于后续修改；本轮只修改规格，尚未新增代码配置或设置界面。
   5.3 初次开始的首个非空候选不额外等待合并；恢复保持本次请求间隔，变化文字按合并规则处理，同文失败按失败重发规则处理。
   5.4 最多一个 OCR 执行中与一个最新待处理帧、一个客户端活动翻译请求与一个最新候选；成功结果与错误均须核对当前会话和文字修订。

## 实施核验

1. 提取并记录既有窗口、录制、滚动长截图及通用样式数值，按明确确认的交互复用；仅对无法满足需求的具体冲突再次澄清。
2. 自动化覆盖暂停恢复、结束与放弃、跨会话隔离、同文成功去重、同文失败再次发送、内容变化丢弃旧失败以及迟到事件失效。
3. 记录设备、目标画面大小、文字量、Provider、网络条件和阶段延迟 P50／P95，按实测调优配置；不把初始值视为延迟达标承诺。
4. 界面效果由用户验收；自动化通过不等同于界面验收。
